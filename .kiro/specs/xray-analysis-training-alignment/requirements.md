# Requirements Document: X-Ray Analysis Training Alignment

## Introduction

The DentalGemma X-ray analysis feature currently suffers from a critical misalignment between how the model was trained and how it is being used in production. The model was fine-tuned on three datasets with simple text descriptions, but the production system requests complex JSON-structured outputs that the model was never trained to produce. This misalignment results in poor model performance, inconsistent outputs, and unreliable analysis results.

This specification addresses the need to align the model's inference behavior with its training data format, ensuring that the system leverages the model's actual capabilities rather than requesting outputs it was not trained to generate.

## Glossary

- **Training_Data**: The datasets used to fine-tune the DentalGemma model, consisting of image-question-answer triplets
- **Inference_Prompt**: The text prompt sent to the model during production use to request analysis
- **Model_Output**: The text response generated by the model in response to an inference prompt
- **Structured_JSON**: A complex JSON schema with specific fields like confidence, urgency, findings arrays, etc.
- **Descriptive_Text**: Simple paragraph-form text descriptions as used in training data
- **Cavity_Detection_Dataset**: Training dataset using clinical photographs (not X-rays) with simple cavity count descriptions
- **OPG_Classification_Dataset**: Training dataset using panoramic X-rays with descriptive paragraphs about pathology classes
- **Dental_Radiography_Dataset**: Training dataset using intraoral radiographs with a single template assessment paragraph
- **Frontend_UI**: The React/TypeScript user interface that displays analysis results
- **Modal_Backend**: The Python FastAPI service that handles model inference on Modal.com
- **TypeScript_Types**: The type definitions that specify the expected structure of analysis results

## Requirements

### Requirement 1: Training Data Format Analysis

**User Story:** As a system architect, I want to understand exactly how the model was trained, so that I can align production usage with the model's actual capabilities.

#### Acceptance Criteria

1. THE System SHALL document the exact answer format used in each training dataset
2. THE System SHALL identify all fields present in training data answers
3. THE System SHALL identify all fields requested in production prompts but absent from training data
4. THE System SHALL quantify the structural complexity difference between training answers and requested outputs
5. THE System SHALL document the image types used in each training dataset (clinical photos vs radiographs)

### Requirement 2: Cavity Detection Training Alignment

**User Story:** As a developer, I want to understand the cavity detection training data format, so that I can align prompts and expectations with what the model learned.

#### Acceptance Criteria

1. THE System SHALL recognize that cavity detection was trained on clinical photographs, not X-rays
2. THE System SHALL document that training answers were simple text like "This dental X-ray shows {n} cavity region(s) detected"
3. THE System SHALL identify that training data contained no JSON structure
4. THE System SHALL identify that training data contained no fields for cavityCount, classification, confidence, urgency, findings arrays, or recommendations arrays
5. THE System SHALL document that training answers were 2-3 sentence descriptions, not structured data

### Requirement 3: OPG Classification Training Alignment

**User Story:** As a developer, I want to understand the OPG classification training data format, so that I can align prompts and expectations with what the model learned.

#### Acceptance Criteria

1. THE System SHALL recognize that OPG classification was trained on panoramic X-rays
2. THE System SHALL document that training answers were descriptive paragraphs about pathology classes
3. THE System SHALL identify the six pathology classes used in training: Healthy Teeth, Caries, Impacted teeth, BDC-BDR, Infection, Fractured Teeth
4. THE System SHALL identify that training data contained no JSON structure
5. THE System SHALL identify that training data contained no fields for pathologyClass, confidence, urgency, findings arrays, or recommendations arrays

### Requirement 4: General Radiography Training Alignment

**User Story:** As a developer, I want to understand the general radiography training data format, so that I can align prompts and expectations with what the model learned.

#### Acceptance Criteria

1. THE System SHALL recognize that general radiography was trained on intraoral radiographs (bitewings and periapicals)
2. THE System SHALL document that training used a single template paragraph for all images
3. THE System SHALL identify that the template described a systematic assessment approach without specific findings
4. THE System SHALL identify that training data contained no JSON structure
5. THE System SHALL identify that training data contained no fields for qualityAssessment, reportSections, findings arrays, or recommendations arrays

### Requirement 5: Prompt-Training Mismatch Identification

**User Story:** As a system architect, I want to identify all mismatches between production prompts and training data, so that I can prioritize alignment efforts.

#### Acceptance Criteria

1. WHEN analyzing production prompts, THE System SHALL identify all requested JSON fields not present in training data
2. WHEN analyzing production prompts, THE System SHALL identify structural complexity mismatches (JSON vs text)
3. WHEN analyzing production prompts, THE System SHALL identify terminology mismatches (e.g., "X-ray" in prompts vs "photograph" in cavity training)
4. WHEN analyzing production prompts, THE System SHALL quantify the number of fields requested that were never trained
5. THE System SHALL generate a mismatch report listing all identified discrepancies

### Requirement 6: Output Format Decision Framework

**User Story:** As a product owner, I want to evaluate different approaches to resolving the training-production mismatch, so that I can choose the best path forward.

#### Acceptance Criteria

1. THE System SHALL document the option to change prompts to request simple text matching training format
2. THE System SHALL document the option to keep JSON but simplify to match training patterns
3. THE System SHALL document the option to retrain the model with JSON-structured answers
4. THE System SHALL evaluate each option's impact on model performance
5. THE System SHALL evaluate each option's impact on development effort and timeline

### Requirement 7: Simple Text Output Approach

**User Story:** As a developer, I want to understand the simple text output approach, so that I can implement prompts that match training data format.

#### Acceptance Criteria

1. WHEN using simple text output, THE System SHALL request paragraph-form descriptions matching training format
2. WHEN using simple text output, THE System SHALL parse key information from descriptive text using pattern matching
3. WHEN using simple text output, THE System SHALL extract confidence indicators from text (e.g., "likely", "definite")
4. WHEN using simple text output, THE System SHALL extract urgency indicators from text (e.g., "immediate", "routine")
5. WHEN using simple text output, THE System SHALL maintain backward compatibility with existing TypeScript types

### Requirement 8: Simplified JSON Output Approach

**User Story:** As a developer, I want to understand the simplified JSON approach, so that I can request only fields that align with training patterns.

#### Acceptance Criteria

1. WHEN using simplified JSON, THE System SHALL request only fields that can be derived from training data patterns
2. WHEN using simplified JSON, THE System SHALL limit cavity detection to: description, cavity_present (boolean), approximate_count
3. WHEN using simplified JSON, THE System SHALL limit OPG classification to: description, pathology_class
4. WHEN using simplified JSON, THE System SHALL limit general radiography to: systematic_assessment (text)
5. WHEN using simplified JSON, THE System SHALL avoid requesting confidence scores, urgency levels, or structured findings arrays

### Requirement 9: Model Retraining Approach

**User Story:** As a machine learning engineer, I want to understand the retraining approach, so that I can prepare datasets with JSON-structured answers.

#### Acceptance Criteria

1. WHEN retraining the model, THE System SHALL generate JSON-structured answers for all training samples
2. WHEN retraining the model, THE System SHALL include all desired output fields in training data
3. WHEN retraining the model, THE System SHALL maintain consistency between training JSON schema and production TypeScript types
4. WHEN retraining the model, THE System SHALL preserve the original image-question pairs while reformatting answers
5. WHEN retraining the model, THE System SHALL validate that JSON schemas are parseable and complete

### Requirement 10: Image Type Terminology Correction

**User Story:** As a developer, I want to correct terminology mismatches between training and production, so that prompts accurately describe the input images.

#### Acceptance Criteria

1. WHEN processing cavity detection, THE System SHALL recognize that training used clinical photographs
2. WHEN processing cavity detection, THE System SHALL update prompts to reference "clinical photograph" or "dental image" instead of "X-ray"
3. WHEN processing OPG classification, THE System SHALL maintain "panoramic X-ray" or "OPG" terminology
4. WHEN processing general radiography, THE System SHALL maintain "intraoral radiograph" terminology
5. THE System SHALL update UI labels and descriptions to match correct image type terminology

### Requirement 11: Frontend Type Alignment

**User Story:** As a frontend developer, I want to align TypeScript types with the chosen output format, so that the UI correctly handles model responses.

#### Acceptance Criteria

1. WHEN the output format is chosen, THE System SHALL update TypeScript types to match the new structure
2. WHEN the output format is chosen, THE System SHALL update UI components to display the new response format
3. WHEN the output format is chosen, THE System SHALL handle both legacy and new response formats during transition
4. WHEN the output format is chosen, THE System SHALL update parsing logic in modal-client.ts to match new format
5. WHEN the output format is chosen, THE System SHALL maintain type safety throughout the frontend codebase

### Requirement 12: Backward Compatibility During Transition

**User Story:** As a system administrator, I want to maintain system functionality during the transition, so that users experience no service disruption.

#### Acceptance Criteria

1. WHEN deploying changes, THE System SHALL support both old and new response formats
2. WHEN deploying changes, THE System SHALL gracefully degrade if JSON parsing fails
3. WHEN deploying changes, THE System SHALL log format mismatches for monitoring
4. WHEN deploying changes, THE System SHALL provide fallback text parsing for legacy responses
5. WHEN deploying changes, THE System SHALL allow gradual rollout of new prompt formats

### Requirement 13: Performance Validation

**User Story:** As a quality assurance engineer, I want to validate that alignment changes improve model performance, so that I can confirm the changes are beneficial.

#### Acceptance Criteria

1. WHEN testing aligned prompts, THE System SHALL measure response quality compared to baseline
2. WHEN testing aligned prompts, THE System SHALL measure JSON parsing success rate
3. WHEN testing aligned prompts, THE System SHALL measure response consistency across multiple runs
4. WHEN testing aligned prompts, THE System SHALL measure response time and latency
5. WHEN testing aligned prompts, THE System SHALL collect user feedback on analysis accuracy

### Requirement 14: Documentation and Knowledge Transfer

**User Story:** As a team member, I want comprehensive documentation of the training-production alignment, so that I understand the system's capabilities and limitations.

#### Acceptance Criteria

1. THE System SHALL document the exact training data format for each analysis type
2. THE System SHALL document the chosen alignment approach and rationale
3. THE System SHALL document prompt templates that match training data format
4. THE System SHALL document parsing strategies for extracting structured data from text responses
5. THE System SHALL document known limitations based on training data constraints
